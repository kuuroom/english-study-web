# English Quest ソースコードガイド

この資料は、初めてプロジェクトを読む人が「どのファイルから読み始めればよいか」「操作したときに何が実行されるか」を理解するためのガイドです。

## 1. アプリの全体像

このアプリは、ページ遷移をせずに3つの画面を切り替えるシングルページ構成です。

1. クエスト選択画面
2. 問題画面
3. 結果画面

3画面はすべて `index.html` に最初から存在します。JavaScriptの `showScreen()` が、表示しない画面へCSSクラス `hidden` を付けることで切り替えています。

```text
起動
  ↓ questions.jsonを読み込む
クエスト選択
  ↓ カードを選ぶ
問題を表示
  ↓ 選択肢を回答
正誤と解説を表示
  ↓ 全問が終わるまで繰り返す
結果を保存・表示
  ↓
再挑戦 または クエスト選択へ戻る
```

## 2. ファイル構成

### `index.html`

画面の骨組みを担当します。主な要素は次のとおりです。

- `player-status`: レベル、EXP、連続正解数、正解数
- `category-screen`: トップとクエスト一覧
- `quiz-screen`: 問題文、ヒント、選択肢
- `explanation-box`: 回答後の正誤と解説
- `result-screen`: 全問終了後の結果
- `level-up`: レベルアップ通知
- `loading-screen`: 問題データ読込中の表示

`id` はJavaScriptから特定の要素を操作するために使い、`class` は主にCSSの見た目へ使っています。

### `css/style.css`

色、余白、配置、アニメーション、スマートフォン対応を担当します。

- `:root`: 共通色と影をCSS変数で定義
- `.app` 以降: アプリ全体とヘッダー
- `.player-status` 以降: プレイヤー情報
- `.adventure-hero` 以降: クエスト選択画面
- `.quest-stage` 以降: 問題画面
- `.feedback-overlay` 以降: 正誤解説
- `.result-card` 以降: 結果と通知
- `@media`: 画面幅に応じたレイアウト変更

`clamp()` は最小値・画面幅に応じた値・最大値を一度に指定する関数です。`env(safe-area-inset-*)` はiPhoneのノッチやホームインジケーターを避けるために使っています。

### `js/app.js`

アプリの動作をすべて担当します。大きく分けると次の役割があります。

- 問題データの読み込み
- クエストカードと選択肢の生成
- 回答の正誤判定
- 画面の切り替え
- EXPとレベルの計算
- 学習記録の保存と復元

### `data/questions.json`

画面へ表示する文法問題と単語を保存します。`grammarUnits` が文法単元、`vocabularyUnits` が単語カテゴリです。JavaScriptから内容を分離しているため、問題・単語の追加だけならゲーム処理を変更する必要はありません。

JSONにはコメントを書けない点に注意してください。末尾の余分なカンマも構文エラーになります。

### `data/assets/`

画面で使う画像素材です。`background-classroom.png`、`background-forest.png`、`background-castle.png` は、カテゴリの順番に応じて問題画面の背景になります。

### `tools/extract-web-assets.ps1`

大きな元画像からWeb用素材を切り出す開発補助スクリプトです。通常のアプリ実行時には読み込まれません。

## 3. JavaScriptの実行順

### 起動時

ブラウザがHTML末尾の `js/app.js` を読み込みます。定数、状態、関数を定義したあと、ボタンへイベントを登録し、最後に `loadData()` を呼びます。

`loadData()` は次の順で処理します。

1. `fetch("data/questions.json")` で問題を取得
2. JSONを `state.data` へ保存
3. プレイヤーステータスを描画
4. クエストカードを生成
5. 過去の挑戦記録を表示
6. ローディング画面を隠す

### クエスト開始時

カードを押すと `startQuiz(categoryId)` が呼ばれます。

1. IDが一致する文法単元または単語カテゴリを探す
2. 単元順に背景画像を選ぶ
3. 問題プールをコピーしてシャッフルし、最大10問を選ぶ
4. 単語の場合は英日・日英を半分ずつ4択問題へ変換する
5. 正解数や問題番号を0へ戻す
6. 問題画面へ切り替える
7. 最初の問題を描画する

配列を `[...category.questions]` でコピーするのは、シャッフルによって元のJSONデータの順番まで変更しないためです。

### 回答時

選択肢を押すと `answerQuestion(selectedIndex)` が実行されます。

- `state.answered` で二重回答を防止
- 選択した番号と `correctIndex` を比較
- 正解選択肢を緑、不正解として選んだものを赤で表示
- 正解ならスコア、連続正解、EXPを加算
- 不正解なら連続正解を0に戻す
- 答え、解説、ポイントを表示

### 全問終了時

`finishQuiz()` がカテゴリ別記録を保存し、正答率から結果メッセージを決めます。その後、結果画面へ切り替えます。

## 4. `state` オブジェクト

`state` は現在のゲーム状況をまとめたオブジェクトです。

| 項目 | 内容 |
| --- | --- |
| `data` | `questions.json` 全体 |
| `currentCategory` | 現在挑戦中のカテゴリ |
| `questions` | 今回の出題順に並べた問題 |
| `questionIndex` | 現在の問題番号。0始まり |
| `correctCount` | 今回の正解数 |
| `streak` | 現在の連続正解数 |
| `answered` | 現在の問題に回答済みか |
| `player` | 累計経験値などのプレイヤー情報 |

画面に表示された値と `state` が食い違わないよう、値を変更した後は `updatePlayerStatus()` などの描画関数を呼びます。

## 5. 問題データの形式

`grammarUnits` は文法クエスト、`vocabularyUnits` は単語クエストの配列です。

| 項目 | 内容 |
| --- | --- |
| `id` | 保存にも使う一意な識別子。公開後は安易に変更しない |
| `name` | カードや問題画面に表示するカテゴリ名 |
| `description` | カードに表示する説明 |
| `questions` | 問題の配列 |

各問題の項目は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| `question` | 問題文 |
| `hint` | 問題文の下に表示するヒント |
| `choices` | 選択肢の配列 |
| `correctIndex` | 正解選択肢の位置。0始まり |
| `answer` | 回答後に表示する答え |
| `explanation` | 文法などの詳しい説明 |
| `point` | 覚え方の要点 |

## 6. ブラウザへの保存

サーバーやデータベースは使わず、ブラウザの `localStorage` に保存します。

### `englishQuestPlayer`

累計EXPを保存します。この値からレベルを計算します。

### `englishStudyProgress`

カテゴリIDごとに次の内容を保存します。

- `bestScore`: 最高正解数
- `total`: 問題総数
- `lastScore`: 直近の正解数
- `attempts`: 挑戦回数
- `totalCorrect`: これまでの累計正解数
- `totalQuestions`: これまでの累計回答数
- `course`: `grammar` または `vocabulary`

冒険記録には、累計正解数÷累計回答数による全体正答率、文法・単語ごとの挑戦済みカテゴリ数、累積正答率が80%未満の苦手カテゴリを最大3件表示します。旧形式の記録は、保存済みの直近得点を最初の累積値として引き継ぎます。

ブラウザや端末を変えると記録は共有されません。閲覧データを削除した場合も消えます。

## 7. よく変更する場所

### 正解時のEXPを変える

`js/app.js` 冒頭の `EXP_PER_CORRECT` を変更します。

### レベルアップに必要なEXPを変える

`EXP_PER_LEVEL` を変更します。CSSの経験値バーは100を基準にしているため、100以外にする場合はバー幅の割合計算も合わせて確認してください。

### 色を変える

`css/style.css` 冒頭の `:root` にあるCSS変数を変更します。

### スマートフォン表示を変える

`@media (max-width: 520px)` 内を変更します。PC側へ影響させずに調整できます。

### 文法単元・単語カテゴリを増やす

問題管理ページを使用するか、`data/questions.json` の `grammarUnits` または `vocabularyUnits` へ追加します。問題背景は3枚を順番に繰り返します。

初期データは中学1～3年の文法37単元・758問と、基礎・中学1～3年の単語43カテゴリ・1,654語です。
単語カテゴリはテーマごとに10～70語程度へ分割し、熟語・複合表現は単独語と分けています。
`tools/expand-full-curriculum.mjs` には全範囲の初期問題・単語と生成処理があります。
このスクリプトは文法単元と単語カテゴリを毎回同じIDで生成するため、繰り返し実行しても重複しません。
生成後は `node tools/validate-question-data.mjs` を実行し、ID・選択肢・正解番号・必須項目を確認してください。

## 8. 注意点

- `index.html`を直接開くと、ブラウザの制限でJSON読込に失敗することがあります。
- カテゴリの `id` を変えると、そのカテゴリの過去記録を引き継げません。
- HTMLの `id` を変更するときは、`js/app.js` の取得処理も同時に変更します。
- CSS変数へ相対画像URLを渡す場合、URLは実際に使われるスタイルシートを基準に解決されます。
- 画像はファイルサイズが大きいと初回表示が遅くなるため、追加時は圧縮を検討してください。
